# 源码运行与构建

## 基础播放环境

Windows 10/11 x64、Node.js 24、Python 3.11，以及 Git。以下命令在 PowerShell 中执行。

```powershell
git clone https://github.com/nadeshikochan/Flowave.git
cd Flowave
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-public-backend.txt
$env:KUMIKO_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
cd electron-lxplayer
npm ci
npm start
```

Electron 会尝试启动本机后端。`KUMIKO_PYTHON` 指定本次终端会话使用的解释器；相关内部命名用于兼容。应用启动后再添加本地音乐目录。

此处安装的是基础后端依赖，支持播放和曲库入口，不包含所有推荐、分析或演奏环境。当前源码快照未完成全新机器安装验收。

## 推荐与其他模型功能

- 推荐环境声明见 `requirements-recommendation-engine.txt`，PyTorch/torchaudio 需按硬件和构建脚本选择匹配版本；MERT 模型可参考 `scripts/install-model.ps1`。
- 标签分析、结构与分轨依赖分别见 `requirements-analysis.txt`、`requirements-structure.txt`、`requirements-stems.txt`。
- 上述文件并非演奏全部模型和外部工具的一键安装方案。旋律识别等能力仍需对应模型、外部运行时及可核验的组件清单；不要将研究缓存作为安装来源。
- 不含模型权重、音乐或第三方在线音源脚本。下载与使用前核对各组件许可。

## 检查与构建入口

在仓库根目录可执行静态边界检查：

```powershell
powershell -NoProfile -File scripts/verify-public-source.ps1
powershell -NoProfile -File scripts/verify-release-data.ps1 -DataDir release-template/data
```

Electron 的 `npm run check` 包含语法检查和 Node 测试；测试入口位于 `electron-lxplayer/test/`。Python 的开发依赖见 `requirements-dev.txt`；本仓库未提供完整 Python 回归测试集。

ZIP 和安装版共用 `scripts/build-desktop.ps1`，需要 Windows x64、Node、Git 和 `uv`。脚本准备固定 Python 3.11.14 构建环境，按哈希锁安装后端依赖，打包轻量 API 和 Electron，并检查实际 ASAR 的依赖、资源清单和数据边界。程序用户无需另装 Node、Python 或构建工具。

```powershell
./scripts/build-portable.ps1
# 本机 npm ci 已完成且依赖未变时
./scripts/build-portable.ps1 -SkipNpmInstall
# Windows 安装版
./scripts/build-installer.ps1 -SkipNpmInstall
```

构建结果分别位于 `electron-lxplayer/dist/portable-时间/` 和 `installed-时间/`，生成相应 ZIP 或 Setup.exe 与 SHA256。`build/portable-delivery/latest-build.json`、`latest-installer.json`记录路径和源码状态。每次创建独立输出目录，测试配置和模型独立存放。

安装版使用Inno Setup 7.1.1，`prepare-inno.ps1`从官方Release获取固定SHA256的编译器，在工作区准备便携工具。安装脚本位于`packaging/windows/installer.iss`。向导给当前用户安装，程序位置和软件数据目录分开选择。系统用户目录只存`Flowave/data-location.txt`位置记录，静默安装通过`/DATADIR="D:\FlowaveData"`选择数据目录。

`packaging/windows/data-location.ps1`先准备目录，复制已有数据并逐文件校验，程序安装成功后原子保存位置记录。失败保留原位置，旧副本交由使用者核对整理。升级自动沿用已保存位置，卸载保留用户数据和位置记录。

安装版的本机隔离验证入口为 `scripts/check-installer.ps1`，涉及实际安装、资源准备、重开、升级、卸载和重装，只接受本仓库生成的安装器。遇到已登记的其他 Flowave 安装或已有快捷方式会停止，须用独立 Windows 账户验收。测试数据存放在 `build/installer-check/`。

`scripts/build-windows.ps1`与独立推荐组件脚本属于早期入口。本仓库没有自动发布工作流，当前产物用于测试，硬件输出和模型功能的验收状态以实际发行说明为准。

## 正式模型小样本验收

`scripts/check-model-delivery.py`用同一份24秒音乐片段，沿正式服务串行验证标签、段落和完整演奏准备，结果发布到独立的`build/`目录。共享已校验资源，分别加载所需模型，保存阶段耗时及结果报告。`--resources`指向已完成安装的工作区`components/resources`，`--output`须在本仓库`build/`内。检查会运行GPU模型，不应作为普通启动步骤。

```powershell
./build/backend-venv/Scripts/python.exe -X utf8 scripts/check-model-delivery.py --audio "D:\Music\song.flac" --resources "D:\FlowaveData\components\resources" --output build/model-check
# 仅回读结果与推荐语义缓存，不重复推理
./build/backend-venv/Scripts/python.exe -X utf8 scripts/check-model-delivery.py --audio "D:\Music\song.flac" --resources "D:\FlowaveData\components\resources" --output build/model-check --stage consumers
```

小样本检查覆盖模型加载、真实推理、源版本/配方与正式存储消费。跨设备质量、长曲和全新机器验收仍需独立记录。卸载清理分类位于`resources/storage-layout.json`，`uninstall-data.ps1`沿该清单限制删除范围，`check-uninstall-options.ps1`仅使用独立登记的验收安装器。

## 工作区启动

Electron入口为`workspace-bootstrap.js`。先校验工作区并设置userData、sessionData和crashDumps路径，取得同一工作区的单实例锁，再载入`main.js`。格式和宿主协议在`.flowave-workspace.json`记录，官方代码仍按可信目录/SHA载入。

切换通过重启参数`--flowave-workspace=<编码后的绝对路径>`传递，新进程覆盖继承的旧数据根。默认位置在完整Vue初始化后才发布，任务繁忙或保存失败时保留当前工作区。主程序版本与workspace-schema兼容性分开管理。工作区聚焦检查位于`electron-lxplayer/test/workspaces.test.js`，只使用临时目录与模拟生命周期，包含实际Vue响应式代理。

## 目录

| 路径 | 内容 |
|---|---|
| 根目录 Python 文件 | 本机 API、曲库、推荐与任务处理 |
| `electron-lxplayer/` | 桌面窗口、播放界面、歌词及资料服务 |
| `packaging/` | 后端与索引组件的打包定义 |
| `scripts/` | 构建、模型安装与公开边界检查 |
| `release-template/` | 发行数据模板和第三方说明 |
| `docs/` | 使用、隐私和源码运行说明 |
